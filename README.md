# 日管控 · 周排查 · 月调度 —— 离线工作台

一个可以放在 U 盘里、断网也能用的食品安全主体责任台账工具。

- **不依赖服务器**：纯静态页面，双击 `index.html` 就能用。
- **不依赖外网**：无 CDN、无字体、无图标库、无统计脚本；Word / Excel 生成、PDF 与 Office 解析全部本地完成。
- **不强制登录**：没有账号、没有积分、没有云同步；数据只存在本机浏览器。
- **AI 可选**：接入任意 OpenAI 兼容接口（DeepSeek / 通义千问 / 硅基流动 / 智谱 / Kimi / 本地 Ollama 等），不配置也能用全部手工功能。

---

## 快速开始

方式一（最简单）：双击 `index.html`，用 Edge / Chrome 打开。

方式二（推荐，便于换端口与调试）：

```bash
cd daily-weekly-work
python -m http.server 8765
# 浏览器打开 http://localhost:8765/
```

首次进入会引导你：选行业 → 勾食品类别 → 填企业名称 → 生成台账。

想先看看效果：在地址后加 `?demo=1`（例如 `index.html?demo=1`），会生成一套"示例 · 稻丰米业"的大米台账与近 20 天记录。看完到「数据与企业信息」清空即可。

## 功能

| 模块 | 能做什么 |
|---|---|
| 工作台概览 | 今日任务、本月执行率/隐患/逾期 KPI、日管控日历（五色标记漏检）、近 14 天条形、待关闭问题、年度事项提醒 |
| 日管控 | 按环节分组逐项勾选「符合 / 不符合 / 不涉及」，一键「其余全部符合」，进度条，检查人与备注，紧凑/详细两种视图，停产休息单独登记 |
| 周排查 | 六段式报告：执行情况 → 隐患 → 上周遗留 → 周期性排查 → 重复性问题 → 研判与下周重点；AI 起草或规则初稿 |
| 月调度 | 八段式纪要：执行情况 → 环节分布 → 各周结论 → 整改关闭 → 月度检查 → 年度事项 → 上月落实 → 研判与下月调度 |
| 不符合项 | 整改中 / 待验证 / 已关闭 / 逾期筛选，行内填写整改情况，验证关闭，Excel 导出 |
| 风险管控清单 | 98 类内置清单（5,623 条），按频次筛选，停用 / 新增 / 改频次 / 改部门，保留"清单原文频次"便于对照核查，导出 Excel；支持**部门对照**、**AI 补充风险点**、**导入企业自有清单** |
| 数据 | 企业信息、JSON 备份与恢复、占用空间统计、清空记录 / 清空全部 |
| AI | 现场问题与照片自动匹配清单并勾选、周排查与月调度研判起草、真实连通性测试 |

### 清单怎么变成"你们公司的清单"

三个入口都在「风险管控清单」页右上角：

**1. 部门对照（推荐先做）**

内置清单用的是通用写法：生产部、品控部、仓储部… 点「部门对照」，左侧列出清单里出现的全部部门及条目数，右侧填你企业的实际名称：

```
生产部      → 控制中心
品控部      → 检测中心
仓储物流部  → 物流中心
设备部      → 工程研究中心
```

左边部门名上悬停会弹出该项目包含的检查项清单（带滚动条，按环节列出风险点与频次），方便判断这个部门到底管什么、该交给谁。右边直接填你企业的部门名，也可以点「按顺序自动匹配」先把企业部门按顺序对上去，再逐行改。

保存后，检查项标签、报告表头、整改责任人全部显示成你的叫法；清单表格里的部门单元格悬停可看到原名。留空表示沿用原名。

**2. AI 补充风险点**

点「AI 补充」，模型会读取当前类别和已有条目，避开重复再补 12~18 条，覆盖人员、设施、原辅料、生产过程、贮存运输、检验等环节。结果先弹出预览表格，勾选后才写入，频次与部门自动归一化（"每班"→日、"每周"→周…）。

**3. 导入企业自有清单**

点「导入清单」，上传 Word / Excel / PDF / 图片（扫描件、照片也行），AI 识别成结构化条目后同样先预览：

- **追加到清单**：只加不存在的条目，同名自动跳过。
- **替换现有清单**：同名条目沿用原 ID（历史台账不断链），被淘汰的旧条目转为"停用"而不是删除，历史记录仍可正常导出。

> 识别与生成都需要先配置 AI 接口；没有配置时这三个功能会引导你去配置，其余功能不受影响。

## AI 接口配置

点右上角「AI 接口」，选择预设或手动填写：

| 字段 | 说明 |
|---|---|
| Base URL | OpenAI 兼容地址，如 `https://api.deepseek.com/v1`（不用带 `/chat/completions`，带了会自动去掉） |
| API Key | 只保存在本机 localStorage；本地 Ollama 可留空 |
| 模型名称 | 支持逗号分隔多个，前一个失败自动切换下一个 |
| 视觉模型 | 可选。上传照片识别时优先使用，留空则用主模型 |
| 温度 / 最大 tokens | 识别建议 0.1~0.3；起草建议 0.4 |

预设：DeepSeek、OpenAI、阿里云百炼、硅基流动、智谱 GLM、Kimi、本地 Ollama。

**注意两点：**

1. **浏览器直连需要服务商允许跨域（CORS）**。多数国产服务商可用；若报跨域，改用本地 Ollama 或自建反向代理。
2. 只有你主动点「AI 识别」或「AI 起草」时，当次输入才会发到你配置的接口，其余时间完全离线。

## 数据与备份

- 存储位置：浏览器 `localStorage`（键 `dwq_offline_v1`）。
- 换电脑、重装系统、清理浏览器数据前，请到「数据与企业信息」导出 JSON 备份，新电脑导入即可，清单与记录一起带过去。
- 一周 31 项 × 365 天，一年约几百 KB，浏览器空间足够；页面会显示当前占用。
- `Ctrl/Cmd + S` 立即保存（平时是自动保存，300ms 防抖）。

## 与原始两个项目的取舍

**留下来的：**

- 98 类权威清单与「清单原文频次」溯源（来自一起食安行「日周月报告」）
- 云端工具打磨过的日历漏检视图、规则初稿、账号级排版规范
- cleanpowerit「日管控工作台」的 AI 快捷录入思路、可换模型接口、多类别合并、紧凑填报
- 两个项目都有的：Word/Excel 原生生成、三态勾选、不符合项闭环

**去掉的：**

- 登录守卫与积分拦截（原始项目里 AI 按钮会被自身守卫拦死）
- 云端依赖（`/api/rzy/state`）与「同步失败即锁页」
- CDN 依赖（pdf.js 改为本地解析）
- base64 内联截图（首屏体积从 1.2 MB 降到 30 KB 级）

## 合规提示

1. 内置清单依据《食品安全风险管控清单》整理，供建立台账时参考，企业应结合自身工艺核实后使用。
2. 工具生成的记录、研判、建议均为初稿，最终结论由食品安全总监、主要负责人确认后归档。
3. 本工具不替代现场检查，也不替代监管部门的检查结论。

## 已知限制

- 浏览器直连 AI 受 CORS 限制，个别服务商需自建代理。
- 扫描版 PDF 无文字层时无法提取文字，请截图后上传（图片走视觉模型）。
- 单机单浏览器存储，多人协作需各自维护台账或合并备份（可后续接入云数据库）。
- AI 生成的条目来自模型，不是官方清单原文，导入或补充后请逐条核对管控措施是否可执行。
- 数据仅在本机，清空浏览器数据会丢失，请定期导出备份。
